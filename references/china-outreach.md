## 一、国内渠道打法表（原文整理）

| 渠道 | 怎么用 | 注意 |
|------|--------|------|
| **V2EX** | 发「分享创造」节点；技术真诚、先给价值再提合作，社区反软文 | 别当广告板，一次只发一个高质量帖 |
| **Linux.do** | 中文开发者/技术社区（Discourse，信任等级制）；发「资源/分享」「开发调优」等合适节点，技术真诚、先给价值 | 信任等级高的账号可发更多节点、帖子自带可信度；勿灌水/软文，违规扣信任等级 |
| **掘金** | 写技术深度专栏（非标题党），文末自然带产品 + 合作入口 | 标题党会被踩；内容要有干货 |
| **知乎** | 技术问答（我们的产品能解决的问题）+ 专栏文章 | 别硬广，先答问题建立可信度 |
| **微信群** | 开发者群/架构群/出海群里，先贡献再私信 | 别群发，一对一私信，尊重群规 |
| **公众号** | 自己写技术公众号；与同量级技术公众号互推 | 互推比硬投广告有效且不 low |
| **即刻 / 少数派** | 开发者密度高的社区，适合冷启动曝光 | 适合早期，量小但质高 |

**渠道选择的速查逻辑**（原文「which channel for whom」的整理）：

| 想触达谁 | 首选渠道 | 原因 |
|---|---|---|
| 开发者关系 / 开发者营销岗 | LinkedIn / 邮件 | 职业化通道；对方的职责就是触达开发者 |
| 独立开发者创始人 / 增长负责人 | X（Twitter）私信或公开回复 | 他们活跃在公开场合；先公开回复赢得私信资格 |
| 用我们产品的公司的工程师 | 社区内互动 → 私信 | 冷私信会被禁言；先在频道里帮上忙混熟 |
| 国内云服务 / AI API / 开发者工具的商务 | 微信私信（先在社区建立可见度） | 国内商务默认微信；先可见、后私信 |
| 泛开发者受众（无具体联系人） | V2EX / 掘金 value-first 公开帖 | 公开、可搜索、让对方主动来 |

## 二、私信公式（原文整理，核心资产）

原文反复强调的私信四要素公式：

1. **先说受众重合，而非自夸**——开头讲「我们的用户和你们的用户是同一批人 / 高度重合」，不要堆 star 数、用户量等自我介绍；
2. **一个具体切入点**——引用一处具体的交集（「你们的某个功能正好出现在我们的典型用法里」）；
3. **一个低门槛请求**——「方便聊 15 分钟吗」「首月免费试」，让对方说「好」的成本降到最低；
4. **不堆形容词**——全条 ≤150 字（微信），一个软性的请求就够，不在私信里丢报价单。

### 微信私信模板（原文，≤150 字）

> [对方称呼]你好，我是 [你的项目] 的维护者。我们是个 [N] star 的 [项目定位] 工具，月下载约 [X] 万，用户和你们 [对方产品] 的开发者高度重合。我们在找合适的长期赞助伙伴，合作形式可以是 README/文档站 logo 位 + 专属口令返佣的混合模式，首月可以免费试。方便聊 15 分钟吗？

**迁移演绎（产品引流版改写示例）**：

> [对方称呼]你好，我是 [产品名] 的作者。我们是个 [一句话定位] 的 [产品类型]，用户约 [X]，和你们 [对方产品/群/号] 的受众高度重合。想聊聊互相推荐/资源置换的合作，形式可以是 [具体形式：互推/返佣/联合活动]，第一次可以先小规模试。方便聊 15 分钟吗？

### 国内商务私信注意事项（原文）

- 微信对非好友或陌生账号的**相似文案群发会风控/限制**——逐条手改、低频发送，绝不群发。
- 先在社区（V2EX/掘金/技术群）建立可见度，再私信——转化率与账号安全度都更高。
- 收款走对公或正规渠道；**GitHub Sponsors 不支持中国大陆**（香港/澳门特区可以），涉及海外合作先核实收款通道。
- 私信里**不报价**。如果数字必须出现，标注「仅供参考，非正式报价」，完整资料（报价卡/媒体包）等对方回复后走邮件或电话。

## 三、中文冷邮件结构（原文模板骨架）

**主题**：[对方产品] 与 [我们的东西]——是否值得聊一次合作？

正文骨架（每段一句事）：

1. **自报家门**：我是 [项目/产品] 的维护者/作者，[一句话用途]，目前 [规模数据：star 数 / 用户量 / 月访问]。
2. **具体交集**（全信最重要的段落）：之所以联系贵司，是因为 [一处具体的交集：例如「我们的快速上手文档默认接你们的 CLI」「在你们的平台上跑我们产品的团队是我们增长最快的用户群」]。
3. **价值主张**：这种交集正是合作的价值点——在目标用户的决策当下触达他们。
4. **软性请求**：能否约 **15 分钟通话**，看看合作是否值得推进；若确实不合适，我会直说，不会强推。
5. **留通道**：日历链接，或直接回复即可。
6. **真实致谢**：感谢 [对方产品]，我们在 [确实在用的场景] 用到它——**只用真实用例**，编造的使用经历一旦被识破即出局。

**跟进邮件**（原模板节奏，与外展纪律一致）：

- 跟进 1（首信后 3–5 天）：一两句话，「怕邮件被淹没，再跟进一次」+ 重复核心数字与请求；
- 跟进 2（7–10 天，换角度给让利）：最后一封——「与其让你冷启动聊 15 分钟，不如直接给个低风险路径：**首月半价/免费试**，双方在签任何长期合作前先看转化」；
- 收到拒绝的回复：优雅收尾——「感谢回复，那就不打扰了。后续若预算有变化，我的联系方式都在」。

## 四、公开帖守则（V2EX / 掘金 / Linux.do value-first 原则）

核心原则：**公开帖子永远先给价值，商业信息只能作为末尾一句「顺便提一下」**，绝不做主帖主题。

- **主帖内容给足干货**：新版本、技术细节、踩坑复盘——赞助/合作信息只在文末带一句（附报价卡或联系方式链接），让感兴趣的人主动来，而非群发。
- **可追踪**：留一个可追踪的链接 + 邮箱/私信入口，把「主动来问」的流量和自然流量区分开。
- **冷却期**：同一论坛短期内不重复发相似的商业帖；V2EX 各节点有各自规则，掘金对营销内容审核较严，按平台规则走。
- **掘金式评论触达**（原文示例思路）：在对方产品相关文章下，以「产品作者」身份补充一句有价值的技术补充（「文中提到的 [功能]，我们在 [我们的产品] 里就是这么实现的，[一句技术细节]」），对合作感兴趣的人自然会顺着来问——这是价值先行、被动获客的打法。

## 五、避免显得 low 的守则（原文汇总）

商业动作做不好会掉粉、掉口碑，守以下几条：

1. **不接灰产/博彩/标题党/擦边**——写一份明确的拒收类别清单，既保护口碑也方便对内拒绝。
2. **商业位克制**——主流做法是低频、规整的呈现（如 README 底部 logo 网格），不是满屏 banner。
3. **透明披露**——合作方标「合作伙伴」，返佣链接标「返佣链接可能产生佣金」，两者**分开标注**，绝不把返佣伪装成中立推荐。
4. **只推自己会无偿推荐的东西**——一次坏推荐损失的可信度，远超那点佣金。
5. **别群发私信**——名单制、3 次触达后关单（节奏详见 ApplyOptimizerAgent 的 `references/outbound-sales.md`，两份文档共用同一套纪律）。
6. **调性匹配**——隐私向的产品不接追踪广告商；安全向的产品不接可疑厂商。
7. **把商业合作和受众价值绑定**——合作页写清楚资源用在哪（维护、内容、活动），让支持者觉得钱花得明白。

## 六、迁移演绎：Buzz 场景的使用边界

- **可直接用**：渠道特性与守则（第一节、第四节、第五节）——这些规律关于「平台文化」而非「卖什么」；私信四要素公式（第二节）——受众重合/具体切入/低门槛请求/不堆形容词对任何合作触达成立。
- **需替换**：原文里「项目维护者身份」「star 数」「月下载量」等自我介绍素材，在产品引流场景换成「产品作者身份」「用户量 / 销量 / 作品集数据」；具体渠道内容（技术专栏、技术问答）适用于技术向产品，非技术向产品需按同一原则（先价值后合作）重选内容形态。
- **不适用**：原文的赞助位定价体系（star 档 × 广告位）依赖「开源仓库流量」这一前提，产品引流不直接套用。
