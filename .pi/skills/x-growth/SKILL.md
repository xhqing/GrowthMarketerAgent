# X Growth — X 平台引流变现工艺

把项目根 `x-algorithm.md` 的推荐算法情报变成**每条内容都过检的执行工艺**：算法怎么给流量，
我们就怎么写、怎么发、怎么养号。X 的机制核心一句话——**算法奖励对话与停留，惩罚外链与好斗；
流量 6 小时衰减，长尾不靠 For You**。本 skill 的所有规则都从这一句推出来。

## 六条铁律（每条内容必过，违反任何一条就改完再交）

这六条是算法机制在执行层的浓缩，逐条讲清 why，理解了才能在没覆盖到的场景里自己判断。

### 1. 正文零外链

链接**只出现在帖串末条 + 首条回复 + bio**，正文任何位置不放链接，惯例话术 `link in reply`。
Why：外链惩罚一路加重，2026 年 3 月起非 Premium 号正文带链接的帖子互动中位数趋近于零——
正文放链接等于主动放弃这条帖子的分发。单帖结构固定为：正文钩子 → 首条回复放带 UTM 的完整链接。

### 2. 对话钩优先

主帖写成提问、可辩论观点或断言式钩子，目标是让人**回复**而不是只点赞。
Why：互动权重序里回复 +13.5（≈27 个赞）、作者回应他人回复 +75（≈150 个赞），
点赞只有 +0.5 基准——一条引发争论（建设性的那种）的帖子，信号价值是一条「大家都同意」
的帖子的几十倍。所以干货帖的末尾要留一个开放问题，而不是把话说完。

### 3. 按 6 小时生命周期运营

- **发帖时间卡美区早晨**（目标受众活跃时段，跨时区排期时按此原则换算）；
- **发后头 30 分钟进入互动状态**：回评论、去利基热帖下写有信息量回复，目标 30 分钟内攒 10 条
  自己帖子的回复——这是算法的病毒触发点（高互动速度 → 推给圈外用户）；
- **同一条干货隔 3-4 天换钩子重发**是正当操作，不是刷屏——6 小时可见性减半、24 小时归零，
  重发是给同一条内容第二次入池机会。

### 4. 养号纪律（TweepCred）

不批量关注；关注列表精而少；每天 20-30 分钟专挑利基高信誉账号（Claude Code / AI agent /
DSH 生态）的热帖写**有信息量**的回复。
Why：账号信誉分低于 65 时每周期只有 3 条帖子进候选池；关注比失衡直接压分；灌水回复是
负反馈候选（举报 -369、屏蔽 -74，一次负反馈抵掉几百个赞）。养号是慢功夫，毁号只要一批关注。

### 5. 语气一律建设性

对比观点可以，嘲讽不可以；可以 disagree，不可 sneer。
Why：情感信号进排序，好斗、引战的框架被系统性降覆盖。引战帖看似互动高，实际被掐分发，
等于白写。

### 6. 常青层 + Starter Pack 中期目标

置顶一条「Start here」帖串，bio 挂落地页链接——点进 profile 的每个人先落到转化路径。
中期目标：持续输出 → 被利基知名 Starter Pack 收录（X 生态目前唯一接近被动长尾的机制）。
Why：For You 没有 6 小时以后的长尾，长尾只存在于三条算法外通道——站内搜索（全文索引长期
有效）、置顶帖、他人转发引用——加上 2026 年 5 月新增的 Starter Pack 入包通道。而 profile
点击本身 +12（≈24 个赞），是高价值信号。帖串、bio、置顶帖的内容要按「常青入口」标准写，
不是发完就忘。

## 产物契约

内容包写到 `artifacts/<campaign>/x.md`（campaign 名与 `plan.md` 一致），对齐
`artifacts/playbook-launch/x.md` 的形态。每条内容必带四件套：

1. **UTM 链接**（唯一 `utm_content`，见下）；
2. **发布时间窗**（对齐排期表的天 + 美区早晨原则）；
3. **发后 30 分钟动作**（回评 + 互动目标）；
4. **回复话术储备**（评论区可预期的 2-3 类问题 + 标准回应，尤其收入证明类）。

## UTM 约定（归因靠它，Echo 复盘靠它）

```
https://<落地页，取自 artifacts/handoff.md>?utm_source=x.com&utm_medium=organic&utm_campaign=<campaign>&utm_content=<内容标识>
```

| 字段 | 取值 |
|---|---|
| `utm_source` | 固定 `x.com` |
| `utm_medium` | 自然流量 `organic` |
| `utm_campaign` | 沿用当前 campaign（如 `playbook-launch`）；新起 campaign 自拟 slug 并同步 Echo |
| `utm_content` | **每条内容唯一**，命名风格 `x-<形态>-<主题>-<序号>`（如 `x-thread-launch-01`、`x-post-algo-02`）；bio 链接用 `x-bio` |

新分配的 `utm_content` 要登记进 `plan.md` 的 utm_content 表，防止重复与漏归因。

## 内容红线（产品口径，防信任事故）

- **不提「早鸟 $35」**：促销码未配置（以 `handoff.md` 最新交接为准，配置生效前任何文案不出现）；
  价格只说 $49 常态价。
- **open-core 边界第一屏明示**：代码 GitHub 免费开源，付费层是手册 / 模板 / 走读的「为什么」层——
  每条内容都要把付费买的是什么说清楚，不装全付费。
- **不编数字**：收入、用户数一律不编；被问收入证明只回公开可验证事实（仓库、流水线产物）。
  文案里引用的数字（价格 / 模块数 / 时间承诺）必须与落地页逐一核对一致。
- **不数文件数**：zip 文件数与落地页口径不一，文案一律回避。
- **链接只指向落地页 / Payloadz**，直链仅用于平台限制放不下落地页链接的场景。
- **TikTok / Gumroad 禁用**，不出现在任何方案里。
