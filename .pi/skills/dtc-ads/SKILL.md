# DTC Ads — 直效 DTC 广告视频工艺

这类广告只服务一个目标：**让刷到的人尽快点击**。前 3 秒拦下手指，中段制造想要，
结尾让点击发生——观众不需要「看完」，更不需要「再看一遍」。本 skill 只做转化向产出：
每条片先定一句话卖点、所有镜头为它服务；同时锁定五个最容易做错的地方：**卖点（先定一句话）、
语言（默认全英文）、收尾（默认无 CTA、只呈现品牌与产品）、一致性（同一道具跨镜同一参考）、成本（先给最优方案再动手）**。

## 何时用

- 做 DTC / 直效 / UGC 风格 / 投流素材类广告视频（电商、门店、应用、服务同理）；
- 需要写脚本、出分镜、生成关键帧与视频、剪音效、做品牌卡、算成本。

不适用：内容型长视频（没有转化目标）、平台账号写作（用 x-growth 等）、内容调研（agent-reach）。

## 七条铁律

### 1. 先定一句话卖点，分镜为它服务

开工第一件事不是找画面，是回答一句：**这条片卖什么？** 把卖点收敛成一句话——
「给谁：有什么不同：凭什么」。写不出这句话，说明这条片还不该开拍。

这句话定了之后，**每个镜头都要有岗位**：Hook（拦下手指）/ Desire（制造想要）/
Proof（证明卖点）/ 收尾（品牌 + 产品；客户要求时附引导语）。没有岗位的镜头——纯装饰的空镜、纯炫技的转场、
纯好玩的梗——一律删掉，不管它多好看。卖点还要在片子里**被说出来**（一句字幕）
和**被看见**（至少一个证明镜头：细节微距 / 对比 / 时间压缩 / 极端条件）。

为什么这么严：广告的钱在点击里，片子只有十几秒——每个镜头要么在推人向点击走，
要么就是在浪费观众和预算。

### 2. 成片默认全英文，不做语言混排

- 画面文字、字幕、品牌卡、旁白、配音：**一律英文**；没有用户明确要求，不得出现中文或任何其它语言文字；
- 需要中文版时，**整条统一为中文单独输出**，不做中英混排（混排最显廉价，也最容易出错）；
- 生成画面里不写文字：提示词统一带 `no text, no people`，所有文字都在后期字幕 / 品牌卡层完成——写得对、拼得对、语言对；
- 投放平台的发布文案属运营层，不在此约束内，但**不要把中文文案塞进画面**。

### 3. 默认不做 CTA：结尾只呈现品牌与产品

- **默认**：片子结尾 = 品牌 + 产品（品牌卡呈现品牌与产品 / 一句利益点即可），**不放 CTA、不在画面里画按钮**；
- 为什么不画按钮：`Shop Now` 这类可点击按钮是**广告系统自带**的（挂在视频外），视频里画一个按钮既点不了、又没有意义，还显得业余；
- **客户明确要求 CTA 时**才做，且用**一句引导语**（字幕或口播），如 `Tap the link below to shop.` / 「点击下方链接购买」——是文字引导，不是假按钮；
- 始终禁止留人话术：`Watch it again` / `Watch till the end` / `Rewatch` / 任何把观众留在视频里的号召；也不要用问句做 CTA；
- 理由：点击由平台的按钮 / 链接完成，视频的职责是让人想要；画假按钮不增加点击，只降低成品观感。

### 4. 合规红线（每条片自检）

- **虚构品牌**：不出现真实品牌 / 商标 / 名人肖像 / 可识别门店；产品与品牌全部虚构或客户自有；
- **不虚构事实性宣称**：不编销量、抢购、排队、用户好评、排名、医疗效果；夸张必须一眼能看出是创意；
- **AI 生成标注**：按投放平台要求开启（上传勾选或描述声明）；
- **素材与音效许可**：只用可商用素材；音效优先选无需署名的免费许可（如 Mixkit），并记录来源与许可。

### 5. 同一个道具，跨镜必须一致

同一条片里出现两次以上的东西——产品、包装、杯器、餐具、容器、标识物——**形状、比例、
颜色、字样必须一致**，观众一眼能看出是同一个东西。做图（关键帧 / 辅助图）时一律适用。

可靠做法只有一种：**先给每个共用道具出一张标准图**（存 `props/`），所有出现该道具的
镜头都带同一张标准图生成（多个道具传多张参考图）；出图后逐镜对照标准图核对，
不一致就重跑该镜（旧图移入 `archive/`，不删除），不带进下一步。

为什么严格：道具不一致就是穿帮——观众会瞬间出戏，前面攒的卖点和信任一起废掉；
而且越往后（生视频、剪辑）返工越贵，必须在关键帧阶段就锁死。

### 6. 开工先给成本方案（默认动作）

每次接到制作任务，**先输出成本方案**再动手：用哪个模型 / 分辨率打样、哪个定稿、预计总额、
更省的可选走法。价目与决策规则见 `references/cost-optimization.md`（当前覆盖火山方舟
- **外部工具调研**（含 ChatCut 等：能补什么、免费额度够不够、与自建管线的关系）见 `references/tools.md`。
直充；以后接入别的平台 / 套餐时在该文件新增分节）。

### 7. 定稿（提分辨率）阶段只动分辨率

**默认不单独做「定稿」这一道**（480p 一遍即定稿）；客户明确要求高画质时才有「定稿」= 把已验收的版本换成原生分辨率，**内容一律不动**：构图、道具数量、动作、字幕、混音、时长全部保持验收版；只把 480p 素材换成原生素材（720p）。

- 定稿不“顺手改”：觉得某个镜头“感觉有点不对”（哪怕是真问题）也**不在定稿阶段改**——先与已验收版本**并排逐帧对比**确认，当作**独立问题单独提出来**讨论，让用户拍板；
- 定稿必须做的一件事：**逐镜与验收版并排复检**（内容一致、只分辨率提升）——不对比就交，就是把验收过的版本改坏的风险；
- 模板：改前先写一句「本次只换分辨率，内容与验收版保持一致」写进 brief / changelog。

为什么这么严：客户/用户验收过的那一版是**基线**，一切后续动作都要围绕它做增量；在定稿阶段动内容，等于把已经过的验收作废，前面花的钱和时间全白搭，而且很容易越改越差。

## 直效结构（15 秒 / 30 秒）

| 段落 | 15 秒版 | 30 秒版 | 要点 |
|---|---|---|---|
| Hook | 0–3s | 0–3s | 反常识 / 悬念 / 点名 / 视觉冲击；静音也能看懂 |
| Desire | 3–10s | 3–15s | 使用瞬间的满足感（satisfying 优先）；痛点点到为止 |
| Product | 10–13s | 15–23s | 产品正面 + 材质细节 + 一句核心卖点 |
| 收尾 | 13–15s | 23–30s | 品牌 + 产品收尾（默认无 CTA；客户要求时才加一句引导语） |

- 画幅 9:16；**生成默认 480p（mini，一遍出片）**、**输出统一 720×1280**（放大，视频号等手机端肉眼无差）——720p / 1080p 生成仅客户明确要求时；**首帧静音可读**（当封面用）；
- 字幕：无衬线、大写优先、下安全区；只写必须说的话；
- 声音：音效先行（质感 / ASMR），音乐次要；响度 ≈ -14 LUFS；
- **人声旁白（推荐默认）**：**每个镜头一句话、读出来**（字幕即该句）——人声是最强的注意力锚，观众跟着句子走、不盯转场；句子**提前 0.1–0.2s 进**（J-cut）顺手缝合切点；句长按镜头时长控（≈2.5 词/秒）；配音来源（`say` / 自录 / 付费 TTS / 真人）、音频链与验收口径见 `references/voiceover.md`；
- **卖点落位**：一句话卖点最迟在 2 秒内以字幕说出，中后段用至少一个镜头证明，品牌卡复述一次；镜头按岗位排（Hook / Desire / Proof / 收尾），不养闲镜；**旁白要密**：「先静后说」（头 2–3 秒纯环境音）看似高级，但多数客户会嫌「旁白太少」——**仅当客户明确要求纯 ASMR 开场时才用**；
- 钩子公式、脚本模板、结尾与 CTA 规则见 `references/copy-patterns.md`；**要「笑点」（喜剧向 / 泰式幽默）时先读 `references/humor.md`**——类型错位、铺垫抽地毯、产品即笑点、deadpan、15 秒压缩法，以及 AI 能做与不碰的笑点清单。

## 生产流程（八步）

1. **定卖点与确认需求**：先把卖点收敛成一句话（给谁 / 有什么不同 / 凭什么），再确认产品、投放平台、时长与画幅、风格参考、品牌资产（logo / 包装 / 参考图）、CTA 需求（默认不做；客户明确要求时才加引导语）；
2. **脚本与分镜**：英文文案 + 逐镜分镜（画面、字幕、音效、时长；每镜标注岗位 Hook / Desire / Proof / 收尾），存 `storyboard.md`；同时给出成本方案；
3. **提示词语言（默认英文）**：官方口径为中英提示词都支持（Seedream 官方称两者都优异、中文在中文文化细节与文字渲染上更强；社区实战认为纯中文最稳、纯英文也能用但不更好）。**本项目默认用英文写提示词**——① 提示词里大量是行业通用英文术语（deadpan / dolly-in / rim light / shallow depth of field），译成中文歧义更大；② 画面内常需出现英文文字（产品印字），英文提示词可直接锚定；③ 跨模型跨平台可复用、与 skill 模板一致。**但 `prompts.md` 里每条提示词都必须给中英对照，且两份都各自放进代码块**（标准图 / 关键帧 / 视频段逐条：**英文原文代码块**供生成、**中文对照代码块**供用户审阅与修改——代码块便于整段复制，散段落不行；多段落的中文对照尤其容易只包住第一行，**改完必须跑 `scripts/check-prompt-pairing.py` 校验**，退出码 0 才算过）——**这是硬性要求**（2026-10-03 用户立）；
4. **关键帧（Seedream）**：先给共用道具（产品、杯器、包装…）各出一张**标准图**存 `props/`；所有出现该道具的镜头都带同一标准图生成（多道具传多张参考图）——道具形状必须跨镜一致（铁律 5）；每镜一张首帧；提示词带 `no text, no people`；**物理约束要写清**（如「气泡只出现在液面以下，水面以上只留静态凝露」）——含混描述会生成穿帮画面；物理问题若在动画阶段仍复现，改用**构图规避**（例：气泡只能在水里 → 俯视构图，让「液面以上」根本不出现在画面里）；存 `keyframes/`；**跨镜同一主角（人 / 动物）必须锁形象（2026-10-04 CRUNCH 实证，返工 ¥12）**：① **先确认「标准图」画出来的就是片子里要用的那一只**（踩坑：标准图画的是短毛狗，而片子里 ③④ 用的是杂毛梗犬 → 照标准图重出反而错向）；② 锁身份最稳的是**多参考图编辑**——`image` 数组传 **[场景图, 主角头部裁剪]**，prompt 写「只换主角、其余完全不变」；③ 抠参考图**必须抠到头部 / 脸**（抠身子会让模型自由发挥成别的品种）；④ 出片后**放大并排逐镜比对主角**；
5. **视频段（Seedance）**：**⚠️ 平台硬限制（2.0 / 2.5 均已实测确认）：不接受含（看起来像）真人人脸的输入素材**（**2.5 也一样**——2026-10-03 用同一张 AI 生成人像关键帧实测 2.5，报同一错误 `InputImageSensitiveContentDetected.PrivacyInformation`；另实测 2.5 首帧模式 **`ratio` 必须传 `adaptive`**，否则报 `InvalidParameter.TaskTypeConstraint`）（AI 生成的人像同样会被判为 `InputImageSensitiveContentDetected.PrivacyInformation` 而 400 拒绝）——**人物镜头只有三条路**：① **不露脸**（只拍手 / 背影 / 侧后 / 不出现头）；② **平台预置虚拟人像库**（官方免费、免授权，可直接用于 Seedance 2.0）；③ **私域真人人像素材**（上传真人 + 肖像授权流程）。默认走 ①（最省事、零合规风险）；**首帧模式**（关键帧作 `--image`）最稳；**默认用 mini · 480p 生成一遍即为成片素材**（手机端投放够用；实测与原生 720p 在全屏观看时肉眼无差）——**不要做「低清打样 → 高清定稿」两遍生成：重新生成就是重新抽卡，内容会变、打样结果保不住**；确实要「只提分辨率、内容不变」时走**超分**（独立产品，需单独开通），否则按「新抽卡」处理（预留重抽预算 + 结果重新验收 + 事先告知客户内容会变）；**要更多像素时先升分辨率、别升档位**：mini@720p 比 2.0@720p 便宜一半且同画质；要 1080p / 4K 用 2.0，要「1080p 且与 480p 样片内容一致」用 **2.5 的官方样片模式（Draft：480p 样片 → 基于样片出 1080p 成片）**（同分辨率下 mini 与 2.0 画质接近；省下的钱拿去多抽几条，因为生成不可复现）（可用模型 ID 见 `references/cost-optimization.md`，用前直查 `GET /api/v3/models` 核对）；**提示词是软条件**——动作方向、否定句（「不要向上」）控不住，只能靠「首帧设计 + 构图规避 + 剪辑取段」三件事硬控：**首帧设计是第一杠杆**（把静帧画成「只可能那样动」的构图，例：冰块要下落 → 画「悬空的冰块 + 平静水面」，不画「已经水花四溅」；**接触约束**：要「脱离 / 滑落」的物体，首帧绝不能画成已经悬空——**2026-10-07 NOPE 镜 3 实证**：要黑壳「整片滑落」，首帧须画「壳仍盖在锅上、前缘刚滑过锅沿（仍贴附）」✓，曾画成「悬在半空、自己弹开」✗ → 模型把「悬浮」放大成「上飘出画」（返工 ¥1.75）；想要的动作方向，首帧就不得出现反向词（要下滑就别写 lift / 掀起 / 弹开），并随首帧写死约束如「like a ceramic tile — never floating, never lifted up」）；**动作方向敏感时用光流量化选条**（`cv2.calcOpticalFlowFarneback`，按区域算纵向速度 vy，正=向下：冰块区应前段明显为正、后段|vy| < 0.1 px/帧；模板匹配 / 帧差会被水花泡沫带偏），别只靠肉眼看条；**抽卡默认「先抽 1 张、通过即用」**（不通过才抽第 2、3 张；**禁止一次性批量抽 3 条**；CRUNCH 实证：8 镜里 6 镜第一张即过，默认 3 抽白花 ≈¥14/片；例外情形见 `references/cost-optimization.md`）；每镜生成 5 秒、剪辑取 2–3 秒；**生成会"吃掉"产品上的细字**（罐身 / 包装印字、logo）——提示词必须写死印字（如 `the can's printed label and lettering stay exactly the same as in the first frame, crisp and legible throughout`），出片后**逐镜放大核对印字**（含**朝向**：产品倒置时文字/图案要一起倒、图标相对字标的位置不能错位），丢了或倒了就用锁印字提示词重跑；**还会"局部静止"**（冰块浮在水里一动不动、水却在动；手机上看很容易漏）——提示词里写死道具持续运动（`keep moving throughout, never frozen in place`），出片后**对关键道具区域量逐帧差**（`crop=... ,tblend=all_mode=difference,signalstats`；帧差 < 1 ≈ 定住，关键道具区域均值应 ≥ 3），不达标就重跑；**跨 take 取音频前先对比动作时序**（定稿 take 的某段音频可能缺失，此时可从打样 take 取同段音频）；视频段临时放项目根（`<slug>-shot-X.mp4`），成片定稿后清理（见产物目录约定）；
6. **声音与剪辑**：**优先用片段自带的生成音频**（与画面天然同步；外挂音效容易出现音画不齐、音色不统一）——模型做不了的声音（品牌卡提示音等）再用免费商用音效补（记录来源与许可）；**生成的运动会出「方向不合物理」**（实测：冰块先向上浮出杯口、再落下；重跑 3 条仍未解决）——**先想剪辑：在现有 take 里找动作正确的时间段，把镜头起点移过去（并同步偏移该段音频）**，比重跑便宜且确定；**旁白与字幕同批交付**（2026-10-07 用户立：给客户看旁白时必须连着字幕一起出，不允许先出"只有旁白"的版本 ✗）；**旁白**：每镜一句、按 J-cut 落位（提前 0.1–0.2s 进），每句 `loudnorm` 统一响度后用 `sidechaincompress` 闪避环境音（旁白句内比句间环境音高 ≥ 8 dB）——见 `references/voiceover.md`；剪辑技巧（**转场：交叉溶解 / 动作衔接 / 相似元素匹配，声音用 J-cut / L-cut 交叠，可选音乐床 + 拍点对齐**——手法清单见 `references/transitions.md`；倒放 / 循环 / 卡点）；统一响度 ≈ -14 LUFS；
7. **品牌卡**：设计卡与成片同尺寸（默认 720×1280；1080p 交付时用 1080×1920）——默认品牌 + 产品 / 利益点，**不画按钮、不放 CTA**（客户明确要求时才加一句引导语）；SVG → PNG 渲染（`rsvg-convert`）；
8. **输出与质检**：**默认 720×1280 H.264**（1080p 仅在客户明确要求时），导出加 `-movflags +faststart` 且时间戳归零（`setpts`/`asetpts`）——避免部分播放器 / 微信里开头黑屏；**视频流时长 ≥ 音频流**（画面比声音长，一般留 0.05–0.1s）且结尾画面（品牌卡）在旁白结束后再留 0.3–0.5 秒——**画面比声音短时，部分播放器（微信 / QuickTime 等）会把尾部渲染成黑屏**；过完质检清单再交付。

## 产物目录约定（固定结构：5 目录 + 4 文件）

每个广告一个目录，**结构固定、不多不少**（临时产物，确认所在项目的 `.gitignore` 已忽略）：

```
tmp/dtc-ads/<slug>/
├── brief.md        ① 需求与创意总说明（含发布方案、成本、打样记录）
├── storyboard.md   ② 分镜脚本（卖点 / 分镜表 / 逐镜要点 / 剪辑说明 / 验收）
├── prompts.md      ③ 提示词与运行手册（生图 / 生视频 / 剪辑参数）
├── <slug>.mp4      ④ 成片（最终视频；纯净版 / 字幕版用后缀区分）
├── props/          共用道具标准图（产品 / 杯器 / 包装）
├── keyframes/      关键帧
├── audio/          音效（含 SOURCES.md 来源与许可）
├── endcard/        品牌卡（SVG 源 + PNG）
└── archive/        被更换掉的旧文件（保留原件，不删除）
```

- **五个目录** = `props/` `keyframes/` `audio/` `endcard/` `archive/`；**四个文件** = 三份文档 + 一条成片（`.mp4`）；
- **过程文件不占位**：Seedance 视频段、试拍图等按需临时存放，**成片定稿后清理**——交付 / 归档时目录里只剩上面 5 目录 + 4 文件；
- **被更换掉的旧文件一律移入 `archive/`**（保留原文件名；同一文件多版本加 `-v1` / `-v2` 或日期后缀）——不留在工作目录，也不删除，历史可追溯；
- 成片多版本命名：`<slug>.mp4`（主版）/ `<slug>-clean.mp4`（纯净版）/ `<slug>-cn.mp4`（中文字幕版）等，都算成片文件。

参考样例：本项目 `tmp/dtc-ads/sensory-loop/`（一条完整的 13 秒广告）。

## 质检清单（交付前逐条过）

- [ ] 卖点一句话已说出（字幕）且有至少一个证明镜头；每个镜头都有岗位（Hook / Desire / Proof / 收尾）
